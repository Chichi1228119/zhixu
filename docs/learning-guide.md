# 知序：9 课边做边学

适合刚开始准备 AI 应用开发岗位的同学。先读懂输入和输出，再读实现细节，不要求一开始就会所有算法。每次只学一课：**当前目标 → 通俗解释 → 实际操作 → 面试设问 → 参考回答 → 小练习 → 反馈**。可以直接说「不懂」「换个例子」「追问我」，拿自己的回答与折叠验收要点对照，再继续。

项目已具备本地导入、检索、摘录、引用、删除和固定评测。默认是 TF-IDF/BM25 字面检索；可选本机 BGE 已实现 512 维神经 embedding 检索，仍不等于生成。另有可选生成 API，但真实生成质量未测。Agent、多人权限、OCR 等尚未实现，不要把计划说成自己的经历。

## 第 1 课：看懂从问题到原文的路径

**目标与解释：**分清检索和生成。像开卷找资料，找到书页是检索，用书页组织新答案才是生成；本地模式直接展示书页摘录。

**操作与代码：**按 [README](../README.md) 启动，问「SN100 默认多长时间采集一次数据？」并点击引用。读 `app/main.py:create_app` 的 `/api/ask`，再读 `app/service.py:KnowledgeService.ask`。

**面试设问：**RAG 是什么，为什么适合企业知识库？

**参考回答：**RAG 先查外部资料，再把片段交给模型生成，便于更新资料与核对来源。本项目默认只完成检索和摘录，配置模型后才生成；选这个起点便于先验证证据链。检索遗漏和误读仍会出错，两个环节要分开验证。

**小练习：**关闭模型配置还能提问，是否说明本项目自己训练了模型？画出本地模式的数据流。

<details><summary>验收与反馈要点</summary>

没有训练。路径是浏览器 → API → 检索 → 原文与来源 → 浏览器；没有生成调用。能指出 `mode="extractive"`、`generation_ms=0`，比背出缩写更重要。若把 TF-IDF 叫作大模型，回到第 3 课再对比。

</details>

## 第 2 课：资料怎么变成可以引用的片段

**目标与解释：**把长资料拆成可查的单位，同时留下页码或段落位置。块太大容易夹杂别的规则，太小会拆开条件和结论。

**操作与代码：**读 `app/ingestion.py:parse_document`、`split_text`。在自己的练习 TXT 里写两段不同事实，中间空一行，上传后打开原文抽屉；再观察长于 900 字符的一段如何切分。只用虚构内容。

**面试设问：**为什么用重叠窗口，是否所有相邻段落都合并了？

**参考回答：**长段默认按 900 字符切、重叠 120 字符，减少切点丢失上下文；短段仍分别保存，PDF 先按页。这样实现简单、出处清楚，但会重复片段，跨段问题也可能漏事实，需要用题集检查。

**小练习：**解释 Markdown 的「第 N 段」为何不等于编辑器第 N 行。扫描 PDF 为什么可能导入失败？

<details><summary>验收与反馈要点</summary>

TXT/MD 按空行划分非空段并编号，标题可能合并到后续正文；行号不是同一概念。扫描件主要是图片，没有可提取文字，当前没有 OCR，系统应报错。不能把修改后缀当作格式转换。

</details>

## 第 3 课：理解字面检索和语义检索的差别

**目标与解释：**BM25 与 TF-IDF 看词项统计；BGE 用预训练神经网络编码句子语义。两者都会找错，不能把“语义”理解为“知道正确答案”。

**操作与代码：**先读 `app/retrieval.py:tokenize` 与 `Retriever.__init__`，观察中文二元三元片段。再读 `app/semantic.py:SemanticRetriever` 的片段编码、问题编码、归一化和 `MIN_SIMILARITY=0.65`。按 README 安装可选模型后，界面可切换「语义检索 · 本机 BGE」；默认仍 hybrid。只观察不同结果，不改冻结确认集和门限。

**面试设问：**TF-IDF 与 BGE 的向量区别是什么？0.65 是否表示有 65% 把握答对？

**参考回答：**默认 TF-IDF 是词项统计权重的稀疏向量，不是神经 embedding；可选 BGE 是本地预训练模型生成的 512 维稠密语义向量，使用 CPU 2 线程，不调用外部 API。语义分支按固定 0.65 余弦门限筛选，它没有概率校准，不表示正确率。36 题确认中，semantic 拒答了全部 8 道无依据题，但有依据误拒答也达到 39.3%，不能说整体更好。

**小练习：**纸上写出「设备断网」的两个相邻双字片段。再解释：若把语义门限调得更严格，为什么可能同时减少误接受、增加有依据漏答？这是否已经证明某个门限最优？

<details><summary>验收与反馈要点</summary>

双字片段依次是「设备」「备断」「断网」，任写两个并能说明滑窗即可。更严格门限会丢掉较低分候选，其中既可能有噪声，也可能有正确依据；未扫描和独立验证，不能宣称最优。不能拿已看过的确认题调门限刷分；TF-IDF 和 BGE 分数都不是答案正确概率。

</details>

## 第 4 课：RRF 融合为什么不保证更好

**目标与解释：**融合像把两个榜单按名次合并，先理解候选是否进榜，再看排序。

**操作与代码：**读 `Retriever.search` 的候选过滤和 `1.0 / (60 + rank)`，对照 [原 64 题报告](../reports/evaluation.md) 三种字面策略结果。页面默认用 hybrid，可选 semantic 是独立检索分支，不是新增到这两个榜单中；BM25、TF-IDF 单独排序可通过 API 或评测观察。

**面试设问：**为何不用 BM25 分数加余弦分数？目前融合提高了多少？

**参考回答：**原始分数量纲不同，RRF 以名次融合避免直接比较分数。三种字面策略共享 TF-IDF 与覆盖门限，BM25 是同候选集的排序消融。原 64 题留出质量指标相同，没有提升证据；semantic 不共享这套门限，也未与它们在 RRF 内融合。

**小练习：**一个片段被共享门限滤掉后，RRF 能否把它恢复？若三策略没有独有命中题，学习任务是否失败？

<details><summary>验收与反馈要点</summary>

不能恢复，融合只排列留下的候选。没有独有命中是实验结论，应记录“未观察到互补提升”，不是删题或改报告。下一步建议先定义独立基线和新的开发实验，不能在已看过的 holdout 上反复调参后继续称独立验证。

</details>

## 第 5 课：引用存在与事实正确是两件事

**目标与解释：**引用像书签，书签指向真实页面，不代表页面支持你说的话。

**操作与代码：**读 `app/provider.py:ModelProvider.generate` 的 `source_ids` 和 `refs` 校验；再读 `app/service.py:_explicitly_missing`。在摘录模式问会员年费问题，观察检索到的配额是不是价格依据。

**面试设问：**有 `[1]` 为什么还不能叫可信答案？

**参考回答：**系统只校验引用编号与片段存在，未做语义蕴含判断。摘录可能拿到相关但不回答所问属性的文本，模型也可能忽略条件。现有留出无依据题只拒答 7/10，应保留误接受，另行评估答案充分性。

**小练习：**问题是「年费多少」，引用只有「最多绑定 20 台设备」，应该记作什么失败？

<details><summary>验收与反馈要点</summary>

无依据问题被误接受；有引用也缺少价格属性依据。应说明资料未提供，不能用容量推算金额。自动关键词覆盖和引用有效率都不能代替人工语义正确率。

</details>

## 第 6 课：跑一份不隐藏失败的评测

**目标与解释：**固定试卷后再比较，避免只挑会答的问题。开发集用于调试，留出集用于定版验证。

**操作与代码：**运行 `scripts/evaluate.py`，读 `app/evaluation.py:calculate_metrics` 与 JSON 的一条结果。记录报告时间、题集哈希、策略、问题 ID、参考和实际来源。再阅读 [36 题确认报告](../reports/semantic-confirmation.md) 与 [协议](semantic-confirmation-protocol.md)：它在门限冻结后已完成一次确认，后续重跑只能称复现，保留原报告，不挑最好结果。两组均未调用真实生成 API；语义组使用了本地 embedding 模型。

**面试设问：**Hit@5、标准来源 Recall@5、完整来源@5、MRR 和拒答率分别衡量什么？

**参考回答：**Hit 看至少一份预期文件出现；标准来源 Recall 先按题计算已召回预期文件占比，再平均；完整来源看所有预期文件齐全；MRR 看首个预期来源排名。拒答率统计无依据题是否标为不足。文件级命中可能是同文件错误段落；预热查询延迟不含 HTTP 或外部生成，BGE 本地编码耗时则包含在语义查询中。

**小练习：**解释留出集 70% 拒答率的分母是多少，并从报告挑一个检索漏召回、一个误接受案例写分析。

<details><summary>验收与反馈要点</summary>

分母是 10 道无依据题，7 道拒答、3 道误接受，不是 44 道总题。例：`holdout-007` 无来源；`holdout-036` 命中会员配额但没年费。先分析原文、切块、门限、排序、状态；不修改固定题来刷分。已看 holdout 可做失败分析，若据此优化需新留出集验证。

</details>

## 第 7 课：删除与缓存也是 AI 应用能力

**目标与解释：**文档删了，数据库片段和内存索引也要更新，否则回答会引用旧资料。

**操作与代码：**读 `app/store.py:Store.delete`、外键 `ON DELETE CASCADE`；读 `service.delete_document` 的 `_retriever=None` 和 `_semantic=None`。上传一份写着「演示资产代号为松果七号」的 TXT，查到后删除，再新会话重新查。

**面试设问：**为什么删表成功还可能检索到旧资料？

**参考回答：**检索索引可能持有旧片段。本项目用外键级联删除数据库片段，再同时使字面与 BGE 片段索引失效，对应策略下次搜索重建。模型对象可缓存，文档向量却必须随资料更新。它适合小规模单机，不是大规模增量索引系统；旧导出快照不自动撤回。

**小练习：**列出删除后应验证的三个位置；重启服务后原电脑 TXT 文件还在是不是删除失败？

<details><summary>验收与反馈要点</summary>

查文档列表、相关 chunks、重新检索来源；可进一步查看自动测试。原电脑文件保留正常，应用只删除数据库副本，未承诺销毁磁盘原始文件或历史快照。若只检查页面数量，尚不足以证明缓存已更新。

</details>

## 第 8 课：把文件当资料，不给它权限

**目标与解释：**PDF 写「忽略规则」不能变成系统指令；网页显示脚本文字也不能运行它。

**操作与代码：**读 `app/static/app.js` 的文本节点渲染、`app/main.py` 的本机 Host/Origin 限制与 `app/limits.py`。上传只含虚构内容的 `<script>` 示例 TXT，查看是否作为文字显示；不要连真实外部模型测试敏感资料。

**面试设问：**提示注入和浏览器脚本注入有什么区别，当前防住了吗？

**参考回答：**前者诱导模型把资料当指令，后者让浏览器执行恶意脚本。文本渲染与 CSP 降低脚本执行风险，本地摘录没有工具执行；可选模型有不可信资料提示，但不能保证免疫提示注入。没有登录和用户隔离，不能直接公网部署。

**小练习：**说明 PDF 页数、解压和文字限制为什么仍不能称作严格资源沙箱。

<details><summary>验收与反馈要点</summary>

当前有 10 MiB、200 页、单页 8 MiB、累计 24 MiB、200 万字符限制，但解析未运行在可强制终止的隔离进程，没有进程硬超时；线程池不等于资源隔离。也没有 OCR。知道限制的具体作用和剩余风险即可，不必背成安全宣传。

</details>

## 第 9 课：把项目变成自己能证明的能力

**目标与解释：**面试不是背代码名单，而是独立复现、解释取舍、定位失败。

**操作与代码：**按 [演示脚本](demo-script.md) 讲 3 分钟，再按 [面试指南](interview-guide.md) 回答追问。检查 `app/main.py` 到 `Store` 的路径，挑一个自己真正能改的小行为，先写预期、再运行验证。不要直接在留出集调参。

**面试设问：**AI 写了很多代码，你做了什么？它算 Agent 吗？

**参考回答：**这是 AI 辅助的学习项目；我应具体说明自己完成并验证的部分，例如独立启动、解释索引更新、分析一条失败、完成有回归检查的小修改。当前是固定检索编排，没有自主规划或工具循环，不能称已经实现 Agent。下一步扩展要先定义工具权限、错误恢复与验收任务。

**小练习：**不看文档用 90 秒讲「问题 → 数据流 → 一个取舍 → 一个失败 → 下一步」，再写两条能拿证据支持的简历描述。

<details><summary>验收与反馈要点</summary>

至少说清默认非生成模式、字面检索局限、7/10 拒答含义、一个具体代码入口，以及自己实际掌握的部分。不能写独立从零开发、企业上线、真实用户数、节省费用或融合显著提升。录音中若只堆名词，回到某个输入输出举例。完成练习不等于自动具备岗位能力，还需能现场解释和修改。

</details>

每课结束可用一句话提交反馈：「我运行了什么，看到什么，我认为原因是什么，还有哪里不懂。」先纠正概念，再决定下一步；不需要一次学完 9 课。
