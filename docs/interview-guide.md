# 知序面试指南：从实际代码回答

面向刚入门的应届生。每题按「概念 → 本项目怎么做 → 为什么这样选 → 局限与验证」组织回答；以下是参考思路，不是已经属于你的个人经历。读完后关闭文档，用自己的话答，并现场指出对应函数。先完成 [学习手册](learning-guide.md) 的练习，再使用 [简历说明](resume-notes.md)。

## 1. 你做的是一个什么项目？

它是本机单用户企业资料问答工作台，完成导入、检索、原文引用、删除与评测。默认字面检索后原文摘录，可选本机 BGE 神经语义检索；两者都不是答案生成，另配置兼容 API 才会生成。资料来自虚构企业，没有真实企业用户或生产部署。

**追问：**请从一次 `/api/ask` 指到检索与数据库入口。应能说明 `main.py → service.ask → search → Retriever`，而不是只列技术名称。

## 2. RAG 与直接问模型有什么区别？

RAG 先检索外部资料，再提供给模型生成，便于更新规则和核对出处；直接问模型可能没有这些私有或新资料。本项目默认停在检索与摘录阶段，不能把它说成已测过生成质量的完整模型方案。

**追问：**只换更强模型能解决漏检吗？不能可靠补回未提供的企业事实，应先看检索与上下文。

## 3. 为什么不是模型微调？

这里要查可更新、带来源的文档，先检索比为每条制度训练权重更易核对。本项目没有训练数据管线或微调实验，也没有证明微调一定无用；当前只实现最小可复现知识库。

**追问：**微调和 RAG 能否组合？概念上可以，但不能宣称本项目已组合或已测收益。

## 4. 文档怎么解析和分块？

`parse_document` 支持 TXT、MD 和文本型 PDF。文本按空行分段，Markdown 标题与正文关联；PDF 按页保留来源。长段通过 `split_text` 按 900 字符、120 重叠切分，易解释但不是按语义自动找边界。

**追问：**块越大越好吗？大块可能混规则，小块可能丢条件；应看固定题的来源、条件完整性和成本，不凭感觉调。

## 5. 为什么保存来源位置？

回答要能返回文件与页码或段落，用户才可核对原文。`chunks` 保存 `document_id, ordinal, location, text`，来源不由模型自由编造。段落编号是解析规则下的计数，不是编辑器行号。

**追问：**引用同一文件就足够了吗？不够，可能指向错误段落，还要核对条件。

## 6. TF-IDF 与 BGE 的向量有什么不同？

默认 TF-IDF 是词项统计稀疏向量，依赖字面重合；可选 BGE 是预训练神经模型输出的 512 维稠密向量，能够表示部分语义关系。BGE 用本机 CPU 2 线程、固定 0.65 余弦门限，不是正确概率。下载由脚本显式触发，普通加载 `local_files_only=True`，不自动联网；语义相似仍不保证答案充分。

**追问：**余弦 0.8 代表 80% 正确吗？不是。确认实验 semantic 虽拒答全部 8 道无依据题，但也误拒答 11/28 道有依据题，不能把门限当作正确率。

## 7. BM25 和 TF-IDF 在这里有什么不同？

BM25 对词频、稀有度和文档长度打分；TF-IDF 用归一化词项权重做余弦相似度。实现复用 `rank-bm25` 与 scikit-learn，没有自行重写算法。两个排序器特征相近，不保证互补。

**追问：**当前 BM25 是独立基线吗？不是，它与其他策略共享 TF-IDF 候选门限，是共享候选的排序消融。

## 8. 为什么用 RRF，公式是什么？

不同原始分数量纲不同，RRF 按榜单名次累加 `1/(60+rank)`。本项目合并 BM25 和 TF-IDF 排名，默认前五片段。共享候选被过滤掉的片段不会被融合恢复。

**追问：**提升了多少？原 64 题的三种字面策略质量指标相同，没有提升证据；可选 BGE 是独立分支，没有加入 RRF，不能报“融合显著提升”。

## 9. Top-K 为什么不是越大越好？

更多片段可能补足多来源，也可能挤入不相关规则、增加重复和模型上下文成本。本项目默认 5，API 限制 1–20；同一文件多个片段会分别占名额。当前未测更大 Top-K 对真实生成的收益。

**追问：**如何选？在开发集固定其他条件做实验，同时看完整来源、误接受、延迟；定版后使用新留出验证。

## 10. 资料不足时怎样拒答？

没有候选会标为 `insufficient`；有候选时，`_explicitly_missing` 用缺失表达与词项重合做启发式判断。它不是语义答案充分性判定；原 64 题留出 10 道无依据题拒答 7 道。另 36 题确认中 hybrid 拒答 5/8，semantic 拒答 8/8，但有依据误拒答也更高，不能混用两组分母。

**追问：**会员配额能回答会员年费吗？不能，属性不同；`holdout-036` 记录了这个失败。

## 11. 怎么判断资料冲突？

`_conflicting_numeric_rules` 对相同句式做数字模板比较，数字组不同则提示核对。它只是简单规则；不同版本、不同适用条件和纯文字冲突不保证识别。演示时应解释检测条件。

**追问：**两款产品保修期不同算冲突吗？不应仅凭数字不同就认定，要看产品条件；不能把冲突提示直接视为事实裁决。

## 12. 为什么有引用仍可能答错？

编号指向真实来源，只证明书签有效。模型可能引用不支持结论的段落、忽略适用条件；本地摘录也可能答非所问。`provider.py` 校验 JSON 与编号集合，没有语义蕴含验证。

**追问：**引用有效率 100% 能叫回答准确率吗？不能；还需逐结论人工核对或另做经验证的语义评审。

## 13. 可选模型接口做了哪些工作？

从服务端 `.env` 或环境读取基础地址、模型和密钥，将问题与检索片段发给兼容 `/chat/completions`，要求结构化答案。客户端设置网络超时、响应大小上限、不跟随重定向；服务端阻止非法编号答案显示。

**追问：**这些测试证明某模型接通了吗？模拟 transport 只证明程序分支；真实服务、生成质量和费用仍未测。

## 14. 文档里的“忽略所有规则”如何处理？

文件是数据，不授予执行权限。本地摘录只返回文字，没有工具执行；可选模型提示强调资料不可信，但无法保证完全免疫提示注入。浏览器使用文本节点与 CSP 降低脚本执行风险，这是与模型注入不同的边界。

**追问：**能直接开放公网吗？不能；没有登录、用户隔离或完整企业安全控制。

## 15. 为什么采用 SQLite，向量存在哪里？

小型单机项目用 SQLite 保存文档与片段，便于安装和检查；TF-IDF 矩阵、BM25 索引与可选 BGE 片段向量在内存，首次选择相应策略或资料变化后构建。BGE 权重保存在 `models/`；文档向量没有存入持久化向量数据库。

**追问：**扩容怎么做？先测资料量、重建耗时与并发瓶颈，再考虑增量索引或独立检索存储，当前不能虚构容量指标。

## 16. 如何保证删除资料后不再检索？

`Store` 开启外键，文档删除级联删除 chunks；`KnowledgeService` 同时让 `_retriever` 和 `_semantic` 失效，相应策略后续重新构建。需要分别验证字面与语义新查询来源，而不只看文档列表。历史快照和磁盘原文件保留。

**追问：**导入同名文件会覆盖吗？不会按文件名覆盖；相同字节 SHA256 去重，变更内容会作为另一份资料。

## 17. 你如何设计评测？

8 份人工编写的虚构资料，原固定 64 题分 dev 20、holdout 44，比较三种字面排序。BGE 实现和 0.65 门限选定后，另冻结 36 题，包含 28 道有依据与 8 道无依据、4 道多源，完成一次 hybrid/semantic 确认。评测用临时数据库，保留明细和哈希；新题仍是同虚构领域，制定者接触过原项目，不能说严格统计独立。

**追问：**看过 holdout 再调参会怎样？它不再是新的独立验证；可用于失败分析，但优化后需要另建冻结题集。

## 18. Hit@5、Recall@5 与 MRR 怎么解释？

Hit@5 指前五片段至少出现一份预期文件的题目比例；标准来源 Recall@5 按题计算已召回预期文件比例再平均；完整来源@5 要求全部预期文件；MRR 是首个预期文件排名倒数平均。都按文件名统计，不等于每段或每句正确。

**追问：**需要两份文件只找一份会怎样？Hit=1、标准来源 Recall=1/2、完整来源=0，不能把命中与完整召回混为一谈。

## 19. 你有哪些实际结果和失败？

原 64 题留出 Hit=31/34（91.2%）、标准来源 Recall=88.2%、完整来源=29/34（85.3%）；无依据拒答 7/10，有依据误拒答 3/34，三种字面排序无质量提升证据。36 题确认中 hybrid/semantic 的 Hit 为 64.3%/60.7%，标准来源 Recall 为 62.5%/58.9%，拒答为 5/8 与 8/8，误拒答为 35.7%/39.3%。这呈现固定门限取舍，没有语义整体更好的证据。

**追问：**为什么不报综合准确率？不同指标含义不同，自动关键词与文件命中不能代替人工答案正确性；小样本不外推生产效果。

## 20. 测试、评测和手动验收有什么区别？

测试检查确定行为，如解析失败、删除、引用编号无效和 API 错误；固定评测衡量这批题上的效果；手动验收确认页面、上传、按钮与启动流程。三者互补，不能用单元测试通过代替浏览器成功或真实模型验证。

**追问：**P95 几毫秒代表用户响应吗？当前只测索引预热后的本地 Python 编排，不含 HTTP、浏览器或外部模型。

## 21. PDF 支持有哪些限制？

最多 10 MiB、200 页，单页解压 8 MiB、累计 24 MiB、提取文字 200 万字符；拒绝加密、损坏和无文字 PDF，没有 OCR。解析运行在线程池，没有隔离进程硬超时，不能承诺任意恶意文件都安全。

**追问：**遇到扫描件如何回答用户？明确暂不支持，先 OCR；不能显示导入成功却没有可用片段。

## 22. 这算 Agent 吗，AI 帮你写代码后怎么证明能力？

当前是固定步骤的检索应用，没有自主规划、工具选择和执行循环，不称已实现 Agent。AI 辅助了实现；我的个人贡献应由实际练习证明：能独立启动、解释数据流、复现失败、提出并验证一个小修改。未掌握的部分如实承认。

**追问：**下一步怎样加 Agent？先选低风险、可验证任务，例如只读工单查询；定义工具输入输出、权限、失败重试、人审节点和独立评测，不直接给予任意系统操作能力。当前未实现这些功能。

## 练习顺序

先回答 1、4、6、10、16、17、22；再准备其余追问。练习时打开真实代码和报告，不靠背文案。能讲清一条失败的证据链，比说“用了很多 AI 框架”更有说服力；不懂的算法细节先说明当前理解，再用小样例推导。
