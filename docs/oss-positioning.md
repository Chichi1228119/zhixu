# 知序开源定位

审查日期：2026-10-27。本文件依据本轮本地源码与同类项目官方 README 编写；开源改造正在实施，计划项不等于已交付。当前未创建公开仓库，不填写仓库 URL、发布徽章、星标或用户评价。

## 面向谁，解决什么问题

面向愿意在自己电脑安装工具的个人、研究者和 AI 应用学习者：把本机资料整理成可搜索的个人知识空间，回答时能回到原文核对；没有生成模型密钥也先完成导入、检索、摘录与删除。需要综合表达时，再显式连接自己的本机或兼容生成服务。

第一版围绕三个任务验收：陌生用户能安装启动；能从自己的资料找到并核对出处；出现没有依据、错误命中或模型失败时，知道系统做了什么并能提交可复现反馈。默认个人空间，模拟企业资料作为可移除的演示样例。

“轻量”是实现范围和交付目标，尚不代表已测得内存、包体或启动速度领先。它需要通过干净安装、依赖清单、冷启动与资源测量证明。

## 选择的差异化方向

| 产品取舍 | 当前基础 | 本轮完成后的可验证表达 |
| --- | --- | --- |
| 无 key 先用起来 | 默认 BM25/TF-IDF 检索与原文摘录可用；BGE 为可选本地检索 | 新环境不填 key、不下载模型，也能导入、查询和删除；明确这不是生成 |
| 证据核对优先 | 片段保存文件及位置，页面可点引用、导出问答快照 | 能逐条回到原文；编号存在不冒充语义正确，资料更新后重新核对 |
| 行为可观察、失败可复现 | 固定题集、逐题结果和启发式拒答；语义策略未证明整体更好 | 用冻结题集和真实失败记录解释取舍，分开报告命中、完整来源、拒答与延迟 |
| 个人空间与小维护面 | FastAPI、SQLite、原生网页；仍有源码目录与 Windows 交付耦合 | wheel 安装后在项目目录外运行，数据写入用户目录，接口与模块容易定位 |
| 自选本机生成服务 | 已有兼容 API 协议封装，尚需 key；真实生成闭环本轮待验证 | GUI 配置本机服务、可无 key 调用 loopback，展示真实模型及失败状态 |

这些是面向目标用户的设计选择，不是同类项目没有这些能力的断言。是否降低安装和核对成本，应以新用户复现与实际反馈判断。

## 首次公开版本的范围

发布前完成可安装 wheel/CLI、安装目录与运行数据分离、TXT/MD/文本 PDF/DOCX 导入、网页模型配置、至少一种真实本机生成服务验证，以及 MIT/第三方声明、CI 和贡献入口。详见 [发布就绪审查](oss-readiness-audit.md)。

OCR、多租户、专用向量数据库、Agent 工具执行、联网资料连接和生产部署可以后续单独设计；它们不是用来填充“功能完美”的列表。默认只绑定本机，不把单用户工具包装成具有企业权限隔离的服务。

## 成功如何判断

一次可审计发布应留下：干净安装和项目目录外启动记录；真实文件导入—引用—删除闭环；本机模型生成的原始响应和引用核验；按当前版本运行的测试与构建结果；公开文件清单、许可证和真实仓库检查状态。

公开后再观察安装成功率、可复现问题、贡献处理与实际使用反馈，样本和收集方式一并说明。没有证据时不写“流行”“广受认可”“最佳”“完美”，也不把旧测试总数当作新版本发布通过证明。
